# Skills

Both agents read this folder (`.agents/skills` and `.claude/skills` point here).

Before a skill drafts or designs, it reads `brand/AGENTS.md`. Before it writes for a reader, scores, or qualifies, it reads `audience/AGENTS.md`. Before it hands work to the owner, it runs `brand/taste.md`. A picture's motion is the JavaScript timeline in that HTML file. The still is the timeline's last frame.

| Skill | When |
|---|---|
| `desk-setup` | Install the Dreamstate plugin for this folder, confirm the workspace, and create brand.local and audience.local from the blank templates. Use at the first session. It does not post, send, or spend. |
| `workspace-check` | Confirm the active Dreamstate workspace before a write or a spend. Use at the start of a later session. It does not draft or send. |
| `context-intake` | Turn the owner's notes into Company Context pages: Ideal Customer, Proof, and Tone of Voice, plus Product Information when it is missing. Use when the pages are empty or wrong. The reader stays in audience.local. It does not invent claims. |
| `voice-card` | Derive voice rules from the owner's own samples and edits. Use when Tone of Voice or brand.local/voice.md is thin. It does not import another person's voice. |
| `local-brand` | Help the owner fill brand.local from the blank templates. Use when identity, voice, style, or tokens are missing. It writes only values the owner supplied. |
| `vault-find` | Search the local vault before drafting and add a concept back after the owner accepts a piece. Use when you need a prior note. It does not call Dreamstate. |
| `pillar-map` | Define content pillars, the reader for each, and the job in the funnel, from the owner's audience and offer. Use once, when the notes are empty. It does not draft the posts. |
| `week-spread` | Turn one sourced idea into a brief and the pieces the owner asked for: script, letter, X, LinkedIn, picture. Use for the week's set. It does not schedule or publish. |
| `week-board` | Update the local status board and, if the owner asks, mark a day on an existing Dreamstate draft. Use after the pieces exist. A day mark is not a schedule. |
| `source-notes` | Build a short evidence brief for a content question from primary sources the owner supplied or a Dreamstate read. Use before a claim-heavy draft. It does not invent findings. |
| `cross-cut` | Split one long source into distinct pieces that share its facts and voice. Use for an interview, a letter, or a talk. It does not add new claims. |
| `opening-line` | Write or compare LinkedIn opening lines in the owner's voice, inside the feed fold. Use for hook options or a first-line edit. It does not write the rest of the post. |
| `linkedin-draft` | Draft or revise one LinkedIn post from the vault, the brand files, and allowed proof. Use for a single post. It does not schedule or publish. |
| `x-draft` | Draft a short X post or thread from a sourced idea in the owner's voice. Use for X copy. It does not publish. |
| `x-week` | Plan X posts with the owner from three lanes: adapted LinkedIn pieces, notes they captured, and launches they already have. Use for an X slate. It does not post. |
| `x-scan` | Turn posts the owner pasted, or a Dreamstate read that returns them, into sourced angles. Use for a niche scan. It does not require a new X login and does not invent reach. |
| `x-essay` | Write a long X article from the owner's letter, framework, or vault notes, with pictures only where they explain a claim. Use when they want a long X piece. It does not publish. |
| `essay-to-linkedin` | Adapt a finished essay into a LinkedIn article draft and a short share post, keeping the claims. Use after x-essay. It does not upload or publish. |
| `letter-draft` | Write one letter or newsletter issue with a single takeaway from sourced material. Use for the long written piece in a week. It does not send email. |
| `essay-draft` | Write a long document with one argument, examples that stay inside the source, and a claim list the owner can check. Use when the piece is not an X essay and not a LinkedIn article. It does not publish. |
| `frame-build` | Build one portrait, carousel slide, or thumbnail as HTML and CSS, with motion in a JavaScript timeline. Use when a piece needs a picture. It does not publish. |
| `frame-review` | Review a rendered frame at full size and phone width, and a motion filmstrip when one exists. Use after frame-build. The owner is the last reviewer. |
| `station-map` | Draw a process as numbered HTML plates in reading order, with connectors that do not cross. Use for a flow, a funnel, or a system map. It does not publish. |
| `stage-build` | Build a small staged scene in HTML and CSS, with labels as real text, then capture it. Use when the idea is a place or a line of stations. It does not use a 3D library. |
| `record-script` | Write a script the owner can record, with a viewer promise, sourced beats, and a payoff that the footage will actually show. Use before filming. It does not generate footage. |
| `video-blurb` | Write the description, links, and chapters from the final transcript the owner supplied. Use after the cut exists. It does not invent timestamps. |
| `thumb-frame` | Compose the thumbnail in HTML at the thumb size so the title and the picture make the same promise. Use after the title is chosen. It does not generate a face. |
| `thumb-patterns` | Note repeating thumbnail patterns in a set the owner pasted or a tool returned, and brief directions. Use before thumb-frame. It does not treat the set as a market law. |
| `title-pair` | Draft two titles from the script, each claim marked sourced or unsupported. Use before a title is chosen. It does not invent performance. |
| `video-pick` | Decide whether an idea is worth recording, using only evidence the owner can support. Use before record-script. It does not call a video-host API. |
| `video-hold` | Package a finished video folder and optionally save a Dreamstate draft. Use when the file is ready for the owner to upload. It does not upload. |
| `release-reel` | Cut a short launch piece from a beat list and assets the owner already has. Use for a launch. It does not generate footage or a face. |
| `long-cut` | Edit a longer recording into an opener still plus the screen recording, with chapters. Use when a plain trim is not enough. It does not upload. |
| `picture-lock` | Turn an edit list and a recording into one captioned file with ffmpeg. Use for a single pass on footage they supplied. It does not upload. |
| `footage-pass` | Review a supplied video from a transcript or a silence map and write the keeps. Use before a cut. It does not generate pictures of the speaker. |
| `talk-cut` | Join talking-head or screen takes, drop false starts, and keep the native picture. Use for a straight cut. It does not restyle the footage. |
| `clip-select` | Choose complete takes and mark false starts. Use before a short is assembled. It does not export the final file. |
| `clip-audio` | Measure speech loudness and apply only a fix you can hear. Use when the recording is harsh, quiet, or rumbling. It does not master for a platform. |
| `clip-motion` | Burn a cue-timed HTML overlay onto a short without covering the speaker or the captions. Use when the words need a label. It does not replace the footage. |
| `clip-assemble` | Run select, audio, overlay, and check for one short. Use when the owner wants a finished short from raw takes. It does not upload. |
| `clip-check` | Probe an export for duration, audio, and caption timing. Use before calling a video done. It does not approve publishing. |
| `step-motion` | Animate a process as HTML plates and capture MP4 and GIF with the repo scripts. Use instead of a separate animation toolkit. It does not publish. |
| `comment-queue` | Draft comments the owner can post on other people's LinkedIn posts, as a local queue. Use when they want replies drafted. It never publishes. |
| `x-reply-queue` | Draft short X replies for posts the owner pasted, as a local queue. Use when they want replies drafted. It never posts. |
| `post-path` | After a post is live, collect engagers, score company and person apart, and draft the next note without sending it. Use when the owner asks what to do with engagers. It does not enroll. |
| `inbox-desk` | List inbox threads that need a person and hand them to a reply draft. Use for triage. It does not send. |
| `thread-reply` | Draft one reply in an existing thread for the owner to send. Use for LinkedIn or email threads already open. It does not start a new sequence. |
| `warm-cadence` | Build a short draft sequence for people who already fit, with a daily cap and fallback copy. Use after fit is accepted. It does not activate. |
| `magnet-build` | Build a giveaway someone can finish without you: promise, worked example, blank file, and a delivery note. Use when the owner wants a lead magnet. It does not send it. |
| `magnet-send` | Prepare a tracked link and the reply that delivers a giveaway, without arming an automatic DM unless the owner accepts that exact rule. Use after magnet-build. It does not send on its own. |
