# Cover

The article gets its own cover. That file is not a profile banner. The feed keeps the portrait.

Build the article frame at 16:9 from the HTML, and set the spacing for that ratio. Do not scale the portrait bitmap into 16:9.

At execution, open LinkedIn's current article-cover help and read the pixel size and the allowed formats. A page there has pointed at 1920 by 1080 for this ratio. Read it again.

The profile-banner size is the wrong target. A size named in `brand.local/style.md` overrides that pixel target. Say which size you used. The ratio stays 16:9.

Keep a result the reader would still recognize. Keep the hierarchy, the type, the palette, and imagery of the real system.

Hold important type off edges a crop is likely to take. Review the native pixels and a narrow width, including the 390px check in `review-graphic`.

Save the HTML next to a PNG or a JPEG that fits the limits you just read.

On a results-led essay, one arrangement is allowed, and it is not a pattern you reuse on other covers: the result line sits on the left, one card in the upper right holds one or two proof numbers, and the real workflow diagram spans the width underneath.

Put a number on that card only when the essay and the Proof page already state it. The window or the unit stays on that number alone.
