# Read

Write one reply in one open thread, in the owner's voice, with the thread link beside the draft. Nothing goes out until the owner accepts that exact text. Use the smallest helpful move. Give help before a signup or a first use.

Offer a call only for a buyer who already qualifies, and only as a question.

Existing threads are in `docs/conversations.md`. A new conversation or cadence is `draft-warm-followups`. Listing the slice is `triage-inbox`.

Read `AGENTS.md`, then the filled files `brand/AGENTS.md` points at, then `audience/AGENTS.md` and `audience.local/ideal-follower.md` when fit matters. The buyer is the Ideal Customer page in Company Context. For a DM, compress `brand.local/voice.md` and `vault/voice/` samples, and reuse this thread's earlier owner lines. Ids are in `docs/tool-map.md`. `tools_get` before `tools_run`.

The fetched schema wins.

Do not add a second context tree. Do not put reply shapes in a side file. These rules are the set.

`whoami` before the first write or spend. If more than one workspace is listed, ask which, and stop.

A comment on someone else's post is `draft-linkedin-comments`: one to three lines, a concrete observation or a question, almost never a pitch. A long post or an article is `write-linkedin-post`. This skill writes neither.
