name: frame-build
description: "Build one portrait, carousel slide, or thumbnail as HTML and CSS, with motion in a JavaScript timeline. Use when a piece needs a picture. It does not publish."
---

Follow `docs/skill-frame.md`.

Build a picture the owner can still edit. Read the brief, the post, and `docs/picture-rules.md`. Read `brand/AGENTS.md`, then the filled `brand.local/` files: identity, voice, style, and tokens. Write for the person in `audience.local/ideal-follower.md`. Claims come from the post and the Company Context pages `brand.local/identity.md` names. A logo, photo, or icon needs `brand.local/assets/README.md` plus the file the README allows. If a required file is missing or blank, stop and ask. Do not guess a color, a font, or a claim. The template has no approved kit.

From the brief, take who reads it, the takeaway, the lines that must appear, the pixel size, and the next action when one exists. The relationship is one claim, a sequence, a comparison, a hierarchy, evidence, or a look back. Before drawing, write three HTML-comment notes: the focal element; reading order before drawing (what enters, what changes, what the reader leaves with); how type, space, and material express that idea.

Teaching frames use labels people can follow. Each plate states a label and a fact true at that step, in up to three lines under the name. Number fewer, larger plates in one nameplate style. On overflow, cut a line or add a slide rather than shrink type.

The post needs a headline, earned points, and attribution. Keep lines as written. Smoother wording is a rewrite. Leave it out. The whole post stays off the frame. Keep the sequence, the figures, and the limits that change meaning. Add no figure the source lacks. Skip a screenshot you lack.

An instructional plate says what to do, or one fact the reader can act on. Start with a verb. Name the object: a folder, a command, or a weekday. A line that only describes does not belong. A quotation, an editorial line, and a proper name keep their grammar.

Take sizes from `docs/picture-rules.md` unless `brand.local/style.md` filled that row and `brand.local/tokens.css` mirrors it. A portrait and each slide are 1080×1350, at 1x and 2x. The phone check uses width 390. The thumbnail is 1280×720. The MP4 is 1080×1350, H.264, 25 fps, `yuv420p`, faststart. The GIF is 720×900, 15 fps, palette, under 5 MB. A blank style row uses this table; say so. These export targets are for this repo. Look up the live platform limit when needed. Ask only when an open question would change the words or the format.

Import `brand/tokens.css` so names resolve. Owner values live in `brand.local/tokens.css`. `DeskTimeline.previewStandIn` fills preview colors while tokens stay unset, so the checkout can render. Do not hand the preview stand-in to the owner. A choice made here stays in this file; it is not a new brand rule. Do not add logo, signature, palette, decorative footer, or a call to action the brief did not supply.

Spacing, hierarchy, and relationships do the work. Ban diagrams inside quotations. Do not stamp a card per slide. Use HTML text, not flat images or paths. Keep labels apart. Connectors do not cross or cover type. Keep contrast readable. Use a vertical rail or left-to-right row. If connectors cross, change the layout and render again. Draw process plates or SVG. Keep product screenshots whole. Owner photos stay unchanged. Do not generate faces. Ban third-party logos, photos, and illustrations. Use fonts the asset README lists. Do not fetch fonts into the repo. Confirm faces are on screen.

A carousel is 5 to 12 slides. Stay at 7 unless the brief gives a reason in range: hook, problem, idea's frame, slide per step, close. Give each slide one job. Keep a continuous sequence. The footer shows the slide number. The portrait file is `pictures/frames/portrait.html`. Each slide file is `pictures/frames/carousel-slide.html`, one file per slide. The thumbnail file is `pictures/frames/thumb.html`. Replace the shell copy. Show a next step only when the brief has one worth taking. A giveaway uses a connect line and the comment keyword you will reply to. Otherwise ask them to save it. Do not invent a deadline or how many already joined.

Motion is a JavaScript timeline. `pictures/timeline.js` exposes `DeskTimeline`. Call `track(start, end, apply)`. `apply(eased, t, raw)` writes styles, SVG attributes, or canvas pixels. `seek` uses ease-out cubic. `DeskTimeline.install` sets `window.__timeline`, `window.__seek`. Capture drives `__seek`. CSS does not animate, and it has no transitions or keyframes. Plates start at `opacity: 0`. The timeline overwrites them. Nothing flashes. Parts move in reading order, 0.4 seconds, no bounce or overshoot. Call to action shows by 2.3 seconds. Hold 6 seconds. Ends match. Loops must not jump. A GIF opens empty at `__seek(0)`. A still is `__seek(duration)`. Duration comes from `DeskTimeline`, not the manifest. Write the still if MP4 or GIF fails.

`npm run still -- <html>` writes `export/still.png`, `export/still@2x.png`, and `export/phone.png` beside the HTML. `npm run capture -- <html>` walks `__seek`, writes `export/motion.mp4` and `export/motion.gif`. Motion capture is local Playwright. Call `whoami` before writing. Store the page with `social.visuals.source_create`. Then `tools_get` `social.visuals.render_preview`, `social.visuals.render_start` with `scope_hash`, and `social.visuals.render_get`. Read the bytes with `social.visuals.file_get` or `social.visuals.download_url`. GIF and MP4 stay local. A prompt request returns HTML: copy, colors, layout, size. A prompt is not a picture. A flattened raster is not the source. Do not redraw from PNG.

Keep the HTML in a named folder, or with that post's pictures. Save the editable HTML beside `export/`. On a thumbnail, and on any frame a profile image will cover, keep type inside the safe inset. Check that crop.

Inspect the 1080px PNG and 390px view, and the thumbnail at 1280×720. Check words, hierarchy, clipping, contrast, connector collisions, missing assets, slides, and sequence. Read the filmstrip. Parts are absent at 0 seconds. The picture is complete at 2.3 seconds. The hold ends match. Repair the fault once. Prefer hierarchy, line breaks, spacing, and crop. Render again. Look at the pixels. Decoration comes after. Neither markup nor a script exit of 0 is a review. If the render cannot run or you cannot see pixels, return HTML and name the missed step. Do not call the file rendered or inspected.

State what you reached: HTML ready, render not run; a prompt exists and is not a picture; rendered, not looked at; or rendered and inspected. Run `brand/taste.md` before the owner sees it. Return the editable HTML, the export, the pixel size, and any limit hit. It does not edit shared brand files. Do not publish.
