description: "Build one portrait, carousel slide, or thumbnail as HTML and CSS, with motion in a JavaScript timeline. Use when a piece needs a picture. It does not publish."
---

Follow `docs/skill-frame.md`.

Build one picture the owner can still edit. Read the brief, the post, and `docs/picture-rules.md`. Read `brand/AGENTS.md`, then the filled copies in `brand.local/`: identity, voice, style, and tokens. Write for the person described in `audience.local/ideal-follower.md`. Claims come from the post and from the Company Context pages `brand.local/identity.md` names. A logo, photo, or icon needs `brand.local/assets/README.md` and a file that README allows. A missing or blank required file stops the picture. Ask for the value. Do not guess a color, a font, or a claim. There is no approved kit inside the template.

From the brief, name who reads it, the takeaway, the lines that must appear, the pixel size, and the next action when one exists. Then name the relationship the picture holds: one claim, a sequence, a comparison, a hierarchy, evidence, or a look back. Before drawing, write three notes in the HTML comment. First, the focal element. Second, state the reading order before drawing: what enters, what changes, and what the reader leaves with. Third, how type and space and material express that idea.

A single still can carry the idea with little copy. A teaching frame needs labels a person can follow. Each plate carries a state label, the fact that is true at that step, plus up to three lines under the name. Number the plates. Use one nameplate style. Prefer fewer plates, drawn larger. When the words overflow the plate, you cut a line, or you add a slide. Shrinking the type to fit is not allowed.

Take a headline, the points that earn their place, and the attribution the post needs. Keep the post's lines as written. Smoother wording is a rewrite, so leave it out. The whole post does not go on the frame. Keep sequence, figures, and limits that change what the line means. No figure goes on the frame unless that figure is already in the post's source. Leave out a screenshot you do not have.

On an instructional plate, the line tells the reader what to do, or it gives a fact the reader can act on. Start the instruction with a verb. Name the object: the folder, the command, or the weekday. A line that only describes does not belong there. A quotation, an editorial line, and a proper name keep the grammar they already had.

Sizes come from `docs/picture-rules.md` unless `brand.local/style.md` already filled that row and `brand.local/tokens.css` mirrors it. A portrait still, and each carousel slide, is 1080×1350. Write one file at 1x and another at 2x. The phone check is that frame with its width set to 390. A thumbnail is 1280×720. An MP4 is 1080×1350, encoded as H.264, at 25 fps, pixel format `yuv420p`, with faststart. A GIF is 720×900. Use 15 fps and a palette. Keep the GIF under 5 MB. A blank style row means you use this table, and you say that you did. These numbers are export targets for this repo. When the owner needs the live platform limit, look that limit up. Set ordinary spacing without asking. Ask when the open question would change the words or the format.

The page imports `brand/tokens.css` so the token names resolve. Values the owner set live in `brand.local/tokens.css`. `DeskTimeline.previewStandIn` fills preview colors while tokens remain unset, which lets a checkout render before anyone fills them. Do not hand the preview stand-in to the owner. A choice you made for this file stays in this file. It is not a new rule for the brand. Do not add a logo, a signature, a palette, a decorative footer, or a call to action that the brief did not supply.

Spacing and hierarchy do the work, along with relationships that are true. Do not pour a diagram into a quotation. Do not stamp the same card on each slide. Set the words as real HTML text. Do not flatten them into an image, and do not convert them into a path. Labels stay clear of each other. Connectors do not cross. They also do not cover type. Give the connectors enough contrast to follow. A vertical rail is enough, or a row that reads left to right. When connectors cross, pick a new layout and render again. Draw a process as editable plates or SVG in this file. A product screenshot the owner supplied stays whole. A photo they supplied can sit in the frame unchanged. No generated face. No third-party logo, photo, or illustration. Use a font file the asset README lists. Do not fetch a font file into this repo. After the page loads, confirm that face is the one on screen.

A carousel runs from 5 slides to 12. Stay at 7 unless the brief gives you a reason to use another count in that range: a hook, the problem, the idea's frame, a slide for each step, then the close. Give each slide one job. Keep the sequence continuous. The footer shows the slide number. Start a portrait from `pictures/frames/portrait.html`, a slide from `pictures/frames/carousel-slide.html` (one file per slide), and a thumbnail from `pictures/frames/thumb.html`. Replace the shell copy. Add a next step only when the brief already has one worth taking. A giveaway's next step is a line that asks them to connect, plus a comment keyword you will reply to. Any other picture asks them to save it. Do not make up a deadline. Do not make up how many people already joined.

Motion is a JavaScript timeline inside that HTML file. `pictures/timeline.js` exposes `DeskTimeline`. The scene adds tracks through `track(start, end, apply)`. `apply(eased, t, raw)` writes styles on HTML, attributes on SVG, or pixels on a canvas. `seek` applies ease-out cubic. `DeskTimeline.install` assigns `window.__timeline` and `window.__seek`. Capture drives `__seek`. CSS does not animate. Do not run the motion with transitions or keyframes. You may set a plate to `opacity: 0` at first, so nothing flashes before the script paints it. The timeline overwrites that value. Parts arrive in reading order. Give each part 0.4 seconds. Use ease-out cubic. No bounce. No overshoot. By 2.3 seconds the close is fully on screen, and that includes the call to action. Then hold about 6 seconds. Match the pixels at both ends of the hold. A loop should not jump. Open the GIF on an empty stage at `__seek(0)`. The still is the last seek: `__seek(duration)`. That frame is the end of this timeline. Read duration from the scene's `DeskTimeline`. Leave duration out of the manifest. Write the still even if the MP4 or the GIF fails.

Use the scripts in this desk. `npm run still -- <html>` writes `export/still.png`, `export/still@2x.png`, and `export/phone.png` beside the HTML. `npm run capture -- <html>` walks `__seek` and writes `export/motion.mp4` and `export/motion.gif`. Motion exports go through local Playwright. Dreamstate can store the source and render a PNG or a PDF. Call `whoami` before that write. `tools_get` the preview id `social.visuals.render_preview`. From that result, call `social.visuals.render_start` and pass `scope_hash`. Then read `social.visuals.render_get`. What that contract renders is PNG and PDF. GIF and MP4 stay on the local scripts. If they ask for a prompt, the file you return is still the HTML, with the copy, the colors, the layout, and the size inside it. A prompt does not count as the picture. A flattened raster does not count as the source. Do not redraw from the PNG.

Keep the HTML in the folder the owner named, or with the other pictures for that post. Save the editable HTML beside `export/`. On a thumbnail, and on any frame a profile image will cover, keep type inside the safe inset and check that crop.

Inspect at full size and at the small size. Look at the 1080px PNG and at the file that is 390px wide. For a thumbnail, also look at 1280×720. Check the words, the hierarchy, clipping, contrast, connector collisions, and any missing assets. Check every slide, then the sequence. On a moving piece, read a filmstrip. At 0 seconds the parts are absent. At 2.3 seconds the picture is complete. The two ends of the hold are the same pixels. Repair the worst fault once. Prefer a change to hierarchy, line breaks, spacing, or crop. Add decoration only after that change. Render again and look at the pixels. You are looking. Reading the markup is not a review. A script exit of 0 is not a review. When the render cannot run, or you cannot look at the pixels, hand back the HTML and name the step that did not happen. Do not call that file rendered, and do not call it inspected.

Name the state you actually reached: the HTML is ready and the render has not run; a prompt exists and is not the picture; the file is rendered and you have not looked; or you rendered it and you inspected it. Before the owner sees the picture, run `brand/taste.md`. Return the editable HTML and the export. Name the pixel size and any limit you hit. This picture does not edit shared brand files. Do not publish.
