The shared link and delivery procedure is in `docs/lead-magnet.md`. The message body carries the full destination URL plus UTM, and it never carries `short_url`. Use list-then-replace. `dm_enabled` stays false until the owner says yes on that exact text. Keep keywords in the range 1-20. Pacing stays at the account's own spacing.

`social.outreach.keyword_dm_rules.list` (`artifact_id`) before `keyword_dm_rules.replace`. One omitted rule is deleted. Live replace sends `expected_revision`. Run `node skills/magnet-send/scripts/check-delivery.mjs` before showing it. The script never sends. It rejects keywords outside 1-20, a sent line the duplicate guard would miss, a connect-first line the guard would treat as already sent, a body that uses `short_url` or omits the destination, a reused destination, a keyword that is not a close spelling of the call to action, praise classified as a request, a tightened gap, or `dm_enabled` on without an arm flag.

Decide who is asking. Match a whole-word keyword, plus the typo list. A real request also includes send or share plus the file's noun, a bare "please send", a line that only asks you to send it, or a genuine ask such as wanting the kit. Skip praise and your own comments. Collapse one person's comments into one decision. SECOND_DEGREE, DISTANCE_2, THIRD_DEGREE, and DISTANCE_3 get the connect-first line only. FIRST_DEGREE or DISTANCE_1 gets the file. A missing degree is a skip. Accepting an invite is a separate yes, and it is not this delivery. A quota refusal parks the run until the quota returns, and it can stall later file messages for hours, even on an optional read. Those reads share a small daily budget. Open one only while someone waits and budget remains. Accept an invite only from a person waiting on this file.

Run the duplicate guard. Nobody gets the file twice. Check worksheet row, then replies under comment, then private thread. Hand-handled people are done, keyed by provider id, so the rule leaves them alone. If `social.outreach.keyword_dm_sends.list` already shows this destination, do not also send it by hand. The sent line must include sent, inbox, or dm as a whole word, or a later pass will not recognize it and will write again. Vary the wording by a hash of the person, so a retry repeats the sentence. Every variant passes that word test. The connect-first line must not include those words. A connect-first line already on the comment is not proof the file went out. Only a one-to-one chat counts. Read at most two chat pages, twenty at a time. Proof is a message you sent, still present, containing the destination. Read about the last twenty messages. Keep this order. Send the file message first. Read it back. Then public line. Save intent on worksheet before every external write. Add a receipt column with `tables.columns.add` after `tools_get`. Shape the message, when you have a real first name, as that name, a blank line, a line naming this file, a blank line, and the full destination URL. The noun is the file's name. If there is no real first token, use a neutral stand-in. Do not guess a name.

Pacing stays at the account's own spacing. Do not tighten it. Do not invent a spacing API. Read `senders.linkedin_accounts.list`. Use limits, today's usage, and working hours only when present; if absent, say so. A shorter gap is refused, and it burns the cycle. Expect twenty to thirty actions an hour, and about ten people. The owner may shorten the gap for safety. This skill never does. Stay inside working hours and stop a few minutes early. Skip days the account does not name as working. If your zone is not the account's zone, the hours check did not run. Say so. Saturday and Sunday are half volume unless the weekend is full volume. A health factor from zero to one lowers the cap the same way. The floor is one, not zero. Count the warmup cap. Leave two message slots in reserve. A spacing, rate-limit, or hours refusal that is not an unknown state returns the row to waiting. Retry inside the account's own limits.

One pass, unless you are only filling missing public lines, covers about 150 comments, 12 file messages, 6 connect-first lines, and 12 sent-lines. More than 500 comments stops the scan on purpose. Each pass starts by reading comments. A busy post can lock those reads for many hours, and then nothing goes out. Once it is busy, stretch toward thirty minutes, not fifteen. On a crowded post, send uncertain file messages first, then first-degree people who still lack the file, including people who connected after the connect-first line, then public lines.
