Follow `docs/skill-frame.md`.

One live post, one file, one destination. Call `whoami` before the first write. People who receive the file are not enrolled into a pitch in the same step. `tools_get` before every `tools_run`. The fetched schema wins. This skill does not send on its own.

The message body carries the full destination URL plus UTM. It does not carry `short_url`. `social.content.tracking_links_lookup` (`urls`) first. That read is free, and dry_run executes live, so say it was a read. Then `social.content.tracking_link_create` (`destination_url` required; optional `artifact_id`, `platform`, `custom_slug`, `og`, `utm`). Read back with `social.content.tracking_link_get`. A click figure comes only from fields that read returns, such as `first_click_at`. If the schema has no count, the count is unknown. One unique URL per post. Delivery treats a person as done when that exact address already sits in the private thread, so an address an earlier giveaway used would skip them. Prefer a fragment on the same page, or UTM whose source is `linkedin`, whose campaign is the post slug, and whose content is `dm`.

`social.outreach.keyword_dm_rules.list` (`artifact_id`) before `keyword_dm_rules.replace`, which replaces the whole set. Show every rule that will remain. One you leave out is deleted. The live replace sends `expected_revision` from the artifact read. A stale revision is refused. Re-read. Do not retry the old body. Typo variants go in `keywords` (1–20): the call-to-action word and close misspellings, nothing unrelated. `comment_reply_not_connected` is the public line for someone who must connect first. `comment_reply_sent` is the line after the file has gone out. `dm_enabled` stays false and public replies stay off until yes on that exact text. An enabled rule messages later commenters with no fresh yes. Say that in the ask. Post text, CTA, and keyword must match before you arm anything. The picture has to show that same word, and every link or mention in the post has to open the right page. Owner yes on the rule.

Run `node skills/magnet-send/scripts/check-delivery.mjs` on the spec before you show it. The script never sends. It rejects a keyword list outside 1–20, a sent line the duplicate guard would miss, a connect-first line the guard would treat as already sent, a body that uses `short_url` or omits the destination, a destination reused from an earlier post, a keyword that is not a close spelling of the call to action, praise classified as a request, a tightened gap, or `dm_enabled` turned on without an arm flag in the spec.

Who is asking. Match the keyword as a whole word, and the typo list. Also match a real request: send or share followed by the file's noun, a bare "please send", a line that only asks you to send it, and a genuine ask such as wanting the kit. Skip a comment that only praises. Skip your own comments. Collapse several comments from one person into one decision. Second-degree and third-degree people get the connect-first line only. Labels you may see are FIRST_DEGREE or DISTANCE_1, SECOND_DEGREE or DISTANCE_2, THIRD_DEGREE or DISTANCE_3. The file goes out once they are first-degree. A missing degree is a skip. Do not send a connection request because someone is out of network. Accepting an invite is a separate yes, and it does not live inside this delivery. The invite id is not in the fetched set. Look it up only if the owner asks, then wait. A quota refusal can stall later file messages for hours, even when that read was optional, because the refusal parks the run until the quota returns. Those reads share a small daily budget with other work. Open one only while someone is waiting and budget remains. Accept an invite only from a person waiting on this file.

Duplicate guard. Nobody gets the file twice. Check the worksheet row first, then replies you already left under the comment, then the private thread. A person you already handled by hand is marked done, keyed by provider id, so the rule leaves them alone. If `social.outreach.keyword_dm_sends.list` already shows this destination went to them, do not also send it by hand. The sent line has to include sent, inbox, or dm as a whole word. If it does not, a later pass will not recognize its own reply and will write again. When you vary that wording by person, pick it with a hash of the person so a retry repeats the same sentence. Every such wording has to pass that word test. The connect-first line must not include those words. A connect-first line already on the comment is not proof the file went out. If a reply you wrote is already there and it passes the word test, stop. Read at most three pages of replies under one comment. A leftover cursor refuses the send. An incomplete duplicate check is not a send. Only a one-to-one chat counts. Read at most two pages of chats, twenty at a time. Proof of delivery is a message you sent, still present, whose text contains the destination. Read about the last twenty messages. Accepted by the provider but not yet seen on read-back stays unverified. No chat id on the receipt means review, not a second send.

Order. The file message is first. Read it back. Then the public line. Save intent on the worksheet before every external write. Add that receipt column with `tables.columns.add` after `tools_get`. Do not keep the status only in memory. Without the column, the first real comment has nothing to reconcile against. Empty previews can still pass. An uncertain send is reviewed and is not repeated. Finish the private messages for the pass before any public line, so a timeout only cuts the tail. A do-not-contact flag blocks only a new file message. If you have not fetched a suppression tool, search, then `tools_get`. Do not invent an id. Once you have it, a list that is cut short, or that fills its page, refuses the send. A page that hits its cap, about five hundred, is incomplete. Match on provider id or on the profile slug, ignoring a trailing slash and a query. A flag that only records an inbound reply does not block the file they asked for. After the file is verified, a reply from them stops later automation. The public line still goes out.

Message shape, when the row has a real first name: that name, a blank line, a line that names this file, a blank line, the full destination URL. The noun is the file's name. If there is no real first token, use a neutral stand-in. Do not guess a name.

Pacing. Leave pacing at the account's own spacing. Do not tighten it. Do not invent a spacing API. Read the account with `senders.linkedin_accounts.list`. Use limits, today's usage, and working hours only when that payload includes them. If those fields are absent, say so. A shorter gap is refused and burns the cycle. Expect on the order of twenty to thirty actions an hour on that account, about ten people. The owner may shorten the gap as a safety choice. This skill never does. Stay inside working hours, and stop a few minutes before they end. If the account names working days, skip the others. If the zone you can read is not the account's zone, the hours check did not run. Say so. Saturday and Sunday count as half unless the account marks the weekend as full volume. A health factor between zero and one lowers the cap the same way, and the floor is one, not zero. A warmup cap counts too. Leave two message slots in reserve. When the action cap is spent, stop file messages and public lines. Stop file messages when the message cap or the warmup cap is hit. Stop public lines when the comment cap is hit. If the account state is unknown and this pass already wrote once, wait about two minutes. If the account names a next slot, wait it out, plus a few seconds. A spacing, rate-limit, or hours refusal that is not an unknown outcome puts the row back to waiting. Retry inside the account's own limits.

Bounds for one pass, unless you are only filling in missing public lines: about 150 comments inspected, 12 file messages, 6 connect-first lines, 12 sent-lines. A post with more than 500 comments stops the scan on purpose. Each pass starts by reading comments, and a busy post can lock those reads for many hours, after which nothing goes out. Once it is busy, stretch the pass toward thirty minutes instead of fifteen. Check progress on the worksheet and with `social.outreach.keyword_dm_sends.list` (`artifact_id`). Do not re-read the comments yourself while delivery is live. `social.comments.queue_list` is a paged read. Use the cursor it returns. Do not scrape in a tight loop. `social.linkedin_posts.comments_list` needs `account_id` and `post_id`. It is a free external read, and dry_run executes live. If the fetched schema offers both a recent sort and a relevant sort, read both and merge on comment id. Newest comments can be missing from the recent sort. If the relevant read fails, keep the recent list. When the post lists more people than the worksheet, compare those two sorts before you assume a miss. Do not give another job on this account the same quarter-hour. They fight for the account gap, the one that loses looks like an uncertain write, and nothing went out. You do not set that clock yourself. On a crowded post, clear uncertain file messages first, then first-degree people who still lack the file, including people who connected after the connect-first line, then public lines. When two people share a priority, take the one you checked least recently. Public lines come last on purpose. If they go first, replies use up the cap and the file sits for days. Leave reply-thread reads until the end of the pass. Cap them at three. If a pass dies inside one, pause those reads for three hours. After a rate limit, pause them for hours. The thread endpoint can be limited on its own while the comment list still answers. One pass at a time. A pass that starts more than nine minutes after its slot is stale. Skip it. An unconfirmed write may be tried once more after fifteen minutes, then it waits for review. Two tries is the ceiling. At about a thousand worksheet rows, stop and review before you widen the list.

If the only handle you have is a short post link, resolve it to the post id first. Then read the live post with `social.linkedin_posts.get` (`account_id`, `post_id`). It costs 0, calls the network, and has no dry_run. Do not send that mode. Use the id that read returns. For a single comment, prefer `social.comments.reply` plus a drafted private message, and wait for yes on those two texts. `social.comments.approve` posts the public reply (`action_id`, `content_hash`, `approved: true`). A preview pulls the live comment list and does not store a row. You get a plan of each file message and each public line. Read the plan before any pass that can send. Anything that is not a live pass must not send. A dry run that stubs the network and shows zero comments only proves the loader ran. Do not set a credit ceiling that lets the file message finish and then drops the public line, unless those lines are paused on purpose. A price of zero still needs a yes when the replace turns a send or a public line on. People you already finished stay marked done. A pass that only fills acknowledgements posts the missing public lines for people whose file is already verified. It sends no new file message and no new connect-first line, it inspects a smaller slice (about a hundred), and it may post up to about forty sent-lines. A request backfill names the people, at most a hundred, and cannot run in the same pass as acknowledgement-only. You can leave public lines off while comment writes keep timing out. File messages continue. Turn the lines back on only with a yes, then run once for the lines that never posted.

Another campaign. Before a new file message to a first-degree person, find whether they are already in an active send on this network. Open means pending, active, waiting on a connection, or waiting on a signal, or another sender owns them. If you have not fetched that tool, search, then `tools_get`. Do not invent an id. If the full list is cut short, read the active slice once. If that slice is still cut short, refuse. Do not guess the rest. Missing channel data refuses the send. Page each open status in steps of 25. A short page is not the full list. Sixty pages is the ceiling. An empty page refuses the send. Mark them aside. Do not recheck them the same day. Look again after a day. A preview still has a credit ceiling. Do not raise it to hide a truncated page.

Private asks. A request in a direct message, or on a connection note, never reaches the comment rule. Find those threads with `unibox.inbox.unified_list` since the post went live. Keep a thread that matches the keyword and whose outbound text does not already hold the destination URL. A keyword hit is not always a request. Drop a thread that only talks about the subject, and a thread you already answered. Draft each reply with `thread-reply`, in the owner's voice. Show the queue. Send only texts the owner has accepted, oldest first, with a few minutes between them. Before each send, read the thread again for the URL. The comment rule may have delivered the file in between.

When the post outgrows private messages. Private messages are the default. If a post draws more comments than you will answer one by one, hundreds in a day or comment reads are rate-limited, say so and ask whether that post's public reply should carry the link. That change needs a yes on that post. Do not make the change yourself. Then one public reply for each request, whatever their degree, oldest first, with wording that changes by person. If the owner already wrote a reply by hand, follow that wording. Leave about ninety seconds plus jitter between those replies, and never go under the account's own gap. Honor the daily comment cap. Read the cap before you read comments, so a pass that is already over the cap does not spend a read. The duplicate guard checks the worksheet row first, then replies you already left in the thread. If a timed-out reply is less than two hours old, stop before any network call. If the network rate-limits you, stop.

After a live pass, verify with `social.outreach.keyword_dm_sends.list` (`artifact_id`). A public line counts only once it is visible on the post. After any change to the rule, wait until one later pass finishes. A preview alone does not prove the repeating path. If the asking comment is gone after the file was verified, there is no public line to post. Mark that person done.

When a pass fails. An uncertain public write on a busy post ends the pass on purpose. Keep public lines behind the file messages. Reconcile in review by reading each thread. Reset a row that never posted, and clear its saved intent. A scheduled pass fails if it calls `Date.parse` on the tick. It also fails if it calls `new Date` on the tick, or `Date.now` on the tick. Read the ISO text instead. The local checker reads that text without those calls. It does not send. A large enrollment read can come back cut short, and then the campaign check must refuse. If the account says quota enforcement is unavailable, stop. Do not build a side path that performs the same writes. Tell the owner. When a run fails, read `runs_get` and `runs_events`. Take the error text from the last event. Do not invent a field the fetched schema does not have.
