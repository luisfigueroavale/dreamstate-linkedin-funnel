Follow `docs/skill-frame.md`.

Use one live post, one file, and one destination. Call `whoami` before the first write. Do not activate a sequence in the same step as delivering the file. Call `tools_get` before every `tools_run`. This skill does not send.

The shared link and delivery procedure is in `docs/lead-magnet.md`. The message body carries the full destination URL plus UTM and never `short_url`. Use list-then-replace. `dm_enabled` stays false until the owner says yes on that exact text. Keep keywords in the range 1-20.

Call `social.content.tracking_links_lookup` (`urls`) first. It is a free read. A dry_run runs live, so say it was a read. Then call `social.content.tracking_link_create` (`destination_url` required; optional `artifact_id`, `platform`, `custom_slug`, `og`, `utm`) and `social.content.tracking_link_get`. Stop when that exact address is already in the private thread, so an earlier giveaway address skips them. Prefer a same-page fragment, or UTM source `linkedin`, campaign the post slug, content `dm`.

Call `social.outreach.keyword_dm_rules.list` (`artifact_id`) before `keyword_dm_rules.replace`. Omitting one rule deletes it. A live replace sends `expected_revision`. If the revision is stale, re-read it and do not retry the old body. The picture shows the keyword. Every link or mention opens the right page. The owner says yes on the rule. Keep `comment_reply_not_connected` and `comment_reply_sent`.

Run `node skills/magnet-send/scripts/check-delivery.mjs` before showing it. The script never sends. It rejects keywords outside 1-20, a sent line the duplicate guard would miss, a connect-first line the guard would treat as already sent, a body that uses `short_url` or omits the destination, a reused destination, a keyword that is not a close spelling of the call to action, praise classified as a request, a tightened gap, or `dm_enabled` on without an arm flag.

Decide who is asking. Match a whole-word keyword, plus the typo list. A real request is send or share plus the file's noun, a bare "please send", a line that only asks you to send it, or a genuine ask such as wanting the kit. Skip praise and your own comments. Collapse one person's comments into one decision. SECOND_DEGREE, DISTANCE_2, THIRD_DEGREE, and DISTANCE_3 get the connect-first line only. FIRST_DEGREE or DISTANCE_1 gets the file. A missing degree is a skip. Accepting an invite is a separate yes, and it is not this delivery. A quota refusal parks the run until the quota returns and can stall later file messages for hours, even on an optional read. Those reads share a small daily budget. Open one only while someone waits and budget remains. Accept an invite only from a person waiting on this file.

Run the duplicate guard. Nobody gets the file twice. Check the worksheet row, then replies under the comment, then the private thread. Hand-handled people are done, keyed by provider id, so the rule leaves them alone. If `social.outreach.keyword_dm_sends.list` already shows this destination, do not also send it by hand. The sent line must include sent, inbox, or dm as a whole word, or a later pass will miss it and write again. Vary the wording by a hash of the person so a retry repeats the sentence. Every variant passes that word test. The connect-first line must not include those words. A connect-first line already on the comment is not proof the file went out. If a reply is already there and passes the word test, stop. Read at most three reply pages under one comment. A leftover cursor refuses the send. An incomplete duplicate check is not a send. Only a one-to-one chat counts. Read at most two chat pages, twenty at a time. Proof is a message you sent that is still present and contains the destination. Read about the last twenty messages. An accepted send not yet on the read-back stays unverified. No chat id on the receipt means review, not a second send.

Send the file message first. Read it back. Then send the public line. Save intent on the worksheet before every external write. Add a receipt column with `tables.columns.add` after `tools_get`. Do not keep the status only in memory. Without that column, the first real comment has nothing to reconcile against. Empty previews can still pass. An uncertain send is reviewed, not repeated. Finish private messages before any public line, so a timeout only cuts the tail. A do-not-contact flag blocks only a new file message. If the suppression tool is missing, search, then call `tools_get`. Do not invent an id. A cut-short list, or a full page, refuses the send. About five hundred rows on a page means the page is incomplete. Match provider id or profile slug, ignoring a trailing slash and query. A flag that only records an inbound reply does not block the file they asked for. After the file is verified, their reply stops later automation. The public line still goes out.

With a real first name, shape the message as that name, a blank line, a line naming this file, a blank line, and the full destination URL. The noun is the file's name. With no real first token, use a neutral stand-in. Do not guess a name.

Pacing stays at the account's own spacing. Do not tighten it or invent a spacing API. Read `senders.linkedin_accounts.list`. Use limits, today's usage, and working hours only when present; if absent, say so. A shorter gap is refused and burns the cycle. Expect twenty to thirty actions an hour, about ten people. The owner may shorten the gap for safety, and this skill never does. Stay inside working hours, stop a few minutes early, and skip days the account does not name as working. If your zone is not the account's zone, say that the hours check did not run. Saturday and Sunday are half volume unless the weekend is full volume. A health factor from zero to one lowers the cap the same way, and the floor is one, not zero. Count the warmup cap and leave two message slots in reserve. Stop file messages and public lines when the action cap is spent, stop file messages when the message cap or the warmup cap is spent, and stop public lines when the comment cap is spent. After one write with unknown account state, wait about two minutes. If a next slot is named, wait it out plus a few seconds. A spacing, rate-limit, or hours refusal that is not unknown returns the row to waiting. Retry inside the account's own limits.

Unless a pass only fills missing public lines, it covers about 150 comments, 12 file messages, 6 connect-first lines, and 12 sent-lines. More than 500 comments stops the scan on purpose. Start each pass by reading comments. A busy post can lock those reads for many hours, and then nothing goes out, so once it is busy stretch toward thirty minutes, not fifteen. Track progress on the worksheet and in `social.outreach.keyword_dm_sends.list` (`artifact_id`), and do not re-read comments while delivery is live. `social.comments.queue_list` is paged, so use its cursor and do not scrape in a tight loop. `social.linkedin_posts.comments_list` needs `account_id` and `post_id`. It is a free external read, and a dry_run runs live. When recent and relevant sorts both exist, read both and merge on comment id, because the newest can be missing from recent. If relevant fails, keep recent. If the post lists more people than the worksheet, compare the sorts before calling it a miss. Run no other job on this account in the same quarter-hour. Jobs share that gap, a loser looks like an uncertain write with nothing sent, and you do not set that clock. On a crowded post, send uncertain file messages, then first-degree people still missing the file, including anyone who connected after the connect-first line, then public lines. Break a tie by who was checked least recently, and put public lines last so replies do not spend the cap while the file sits for days. Read reply threads at the end, with a cap of three. A pass that dies inside one pauses those reads for three hours, and a rate limit pauses them for hours, because the thread endpoint can limit while the comment list still answers. Run one pass at a time. Skip a pass more than nine minutes after its slot. Try an unconfirmed write once more after fifteen minutes, then it goes to review. Two tries is the ceiling. At about a thousand worksheet rows, stop and review before widening.

For a short post link, resolve the post id, then call `social.linkedin_posts.get` (`account_id`, `post_id`). The cost is 0. It calls the network and has no dry_run. Do not send that mode. Use the returned id. For one comment, use `social.comments.reply` plus the drafted private message, with a yes on both texts. `social.comments.approve` posts the public reply (`action_id`, `content_hash`, `approved: true`). A preview pulls the live comment list and stores no row. It plans each file message and public line. Read that plan before any pass that can send. Anything that is not a live pass must not send. A dry run that stubs the network and shows zero comments only proves the loader ran. Do not set a credit ceiling that finishes the file message and drops the public line, unless those lines are paused on purpose. A price of zero still needs a yes when replace turns a send or a public line on. Finished people stay done. For acknowledgement-only posts missing public lines for people whose file is verified, send no new file message, send no new connect-first line, scan about a hundred comments, and allow up to about forty sent-lines. A request backfill names the people, at most a hundred, and cannot share a pass with acknowledgement-only. Public lines may stay off while comment writes time out. File messages continue. Turn lines on only with a yes, then run once for lines that never posted.

For another campaign, before a new file message to a first-degree person, check whether an active send on this network already has them. Open means pending, active, waiting on a connection, waiting on a signal, or another sender owns them. If the tool is missing, search, then call `tools_get`. Do not invent an id. If the full list is cut short, read the active slice once. If it is still cut short, refuse. Do not guess. Missing channel data refuses the send. Page each open status by 25. A short page is not the full list. Sixty pages is the ceiling. An empty page refuses the send. Mark them aside. Do not recheck them the same day. Look again after a day. The preview still has a credit ceiling. Do not raise it to hide a truncated page.

A DM or a connection note never hits the comment rule. Find threads with `unibox.inbox.unified_list` since the post went live. Keep a keyword match whose outbound text does not already hold the destination URL. A keyword hit is not always a request. Drop subject-only threads and threads already answered. Draft with `thread-reply`, in the owner's voice. Show the queue. Send only accepted texts, oldest first, a few minutes apart. Before each send, reread the thread for the URL. The comment rule may have delivered the file in between.

Private messages are the default. If you will not answer one by one, if there are hundreds in a day, or if comment reads are rate-limited, say so and ask whether that post's public reply should carry the link. That needs a yes on that post. Do not change it yourself. Then send one public reply per request, at any degree, oldest first, with wording that changes by person. Follow a hand-written owner reply. Wait about ninety seconds plus jitter, and never go under the account's own gap. Honor the daily comment cap. Read the cap before the comments so an over-cap pass spends no read. For that duplicate guard, check the worksheet row, then replies already in the thread. If a timed-out reply is under two hours old, stop before any network call. If a network rate limit hits, stop.

After a live pass, verify with `social.outreach.keyword_dm_sends.list` (`artifact_id`). A public line counts only once it is visible on the post. After a rule change, wait until one later pass finishes. A preview alone does not prove the repeating path. If the asking comment is gone after the file was verified, there is no public line. Mark that person done.

On a failed pass, an uncertain public write on a busy post ends the pass on purpose. Keep public lines behind file messages. Reconcile by reading each thread. Reset a row that never posted and clear its saved intent. A scheduled pass fails when a tick calls a date constructor or the clock. Read the ISO text.
