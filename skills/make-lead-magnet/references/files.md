# Lead magnet files

## Format
| The job | Build |
|---|---|
| A decision made again and again | calculator |
| Work that comes back | template |
| A workflow that runs or needs config | repository |
| An inspection with a clear end | checklist |
| A method that needs explaining in words | guide |

A hosted page is not the default.

## Folder `magnets/<slug>/` (copied from `magnets/example/`)
Replace every line and leave no example sentence. A later reader must be able to restart from the same blank.

- `promise.md`: the one sentence.

- `example.md`: one complete pass to that output. The first line says it is an example. Mark any made-up figure as invented, never as a customer result, and use no customer numbers.

- Blank: `blank.md`, or the sheet, checklist, template, or repo it points to. It must be editable.

- `delivery.md`: the keyword, the full URL, and the sentence that carries it. Keep the existing UTM and use no short link. If the resource is unpublished, the address is unknown.

- `README.md` covers these, in order:
  1. who it is for, the problem, the promise, and the pieces
  2. the first result
  3. setup, naming every tool, account, cost, install, price, and unsupported step
  4. the published stable address
  5. after the first result, one optional next step, with extras after that

  It ends with the check. It pays off the promise with no sales conversation in the path.
