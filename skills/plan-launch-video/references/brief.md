# Brief

Read `brand/AGENTS.md`, `brand.local/identity.md`, `brand.local/voice.md`, `audience/AGENTS.md`, and `audience.local/ideal-follower.md`. A missing file or `Status: blank` means stop and ask. Product Information comes as run input: the seat that read the Product Information page in Company Context passes it in the handoff, or the owner supplies it. This skill has no Dreamstate tools, so if neither came in, ask. A product page is a claim about behavior, not proof of it.

Copy `references/templates/brief.md` into the plan and fill what the owner supplied. Ask only for a field that changes a claim or a shot. Keep working on the rest while you wait.

| Field | What it decides |
|---|---|
| What works today | What may appear on screen as real |
| Viewer | Who must recognize the problem in the first five seconds |
| Buyer | Who pays, from the Ideal Customer page |
| Wanted result | The change the viewer wants, in their words |
| Current way | The task, the cost, or the mistake to show |
| Usual alternative | Why switch from it, or from doing nothing |
| Visible difference | The on-screen behavior that proves it |
| Proof on hand | Real outputs, measured results, customer words with permission |
| Action and destination | What the right viewer does next, and where |
| Product type | The library `category` id used to find comparables |
| Proof type | `output`, `live_demo`, `before_after`, `measured_result`, or `concept`, used to find comparables |
| Channel | Where it runs |
| Length (seconds) | Which timed structure to use |
| Aspect | The frame |
| Date and assets | What can be finished in time |

If no product is supplied, return the blank brief, not an invented one.
