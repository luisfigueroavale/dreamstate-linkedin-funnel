# Hooks

These sixteen families are for planning. The launch video library labels its records with the shorter list of `hook_family` ids in its `data/hooks.json`. Never write a planning slug into a library record. The last column gives the library id to use. Save both in the plan, next to the chosen hook.

A hook is the first frame, the first action, the first words, and the first payoff together. Write twelve to sixteen candidates. Each one names its family. Use at least six families.

## The sixteen families

| # | Family | Opens on | Needs in the ledger | Library id |
|---|---|---|---|---|
| 1 | Result first (`result_first`) | The finished output, then where it came from | The output file | `input-output` |
| 2 | Live run (`live_run`) | One real run in real time, no cuts | A clean capture | `input-output` |
| 3 | Surprising action (`surprising_action`) | The most unexpected thing the product really does | A capture of it working | `removed-constraint` |
| 4 | Who it is for (`who_it_is_for`) | The viewer named in one line, then their result | The Ideal Customer page | `product-reveal` |
| 5 | Before and after (`before_after`) | The same task both ways, with fair inputs | Both captures, same input | `comparison` |
| 6 | The old way (`old_way`) | The current painful task, shown, then the fix | A real capture of the old task | `specific-grievance` |
| 7 | Their words (`their_words`) | The problem as the audience says it | A dated, linked source | `specific-grievance` |
| 8 | The buyer's question (`buyers_question`) | A question buyers really ask, answered on screen | Where the question came from | `objection-ownership` |
| 9 | Challenge with proof (`challenge_with_proof`) | A common habit questioned, then proof at once | The proof shot right after | `objection-ownership` |
| 10 | One place (`one_place`) | Several tabs or tools, then one screen doing the job | The real tools the viewer uses today | `removed-constraint` |
| 11 | Control shot (`control_shot`) | The approval step: nothing goes out until the owner says yes | The real approval screen | `objection-ownership` |
| 12 | Measured number (`measured_number`) | One number with its scope on screen | A tool read or a measured file | `measurable-stakes` |
| 13 | Founder fact (`founder_fact`) | One short, sourced fact about why it was built | Only when trust is the gap | `authority-mission` |
| 14 | Build in public (`build_in_public`) | What shipped this week and why | The real change log or commit | `product-reveal` |
| 15 | Zoom out (`zoom_out`) | One output close up, then the system that made it | Both shots real | `input-output` |
| 16 | The mistake (`the_mistake`) | The error or waste on screen, then the fix | A real example, nothing private | `specific-grievance` |

A measured number never comes from an edited runtime. A sped-up shot is not a speed claim.

## Score

Score each candidate 0 to 5 on six tests: clear by second five, specific to this product, proof follows at once, works muted, honest scope, and a reason to keep watching. Keep the total out of 30 next to the family.

Show the top three. Each one gets the first frame, the opening line, the proof bridge (the beat that pays off the line), and the ledger line it needs.

Checks before you keep a hook: pause at second five and say what it is, for whom, and why to keep watching; a newcomer can say it back; it works with the sound off; a rival could not say the same line; a skeptic believes the scope.

Cut these openings: an announcement, company history, a category label, an unmeasured time saving, a superlative, or a montage with no meaning.

A score helps the owner choose. It is not a view forecast, and the family is a label, not a cause.
