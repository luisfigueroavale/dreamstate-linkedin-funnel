name: vault-find
description: "Search the local vault before drafting and add a concept back after the owner accepts a piece. Use when you need a prior note. It does not call Dreamstate."
---

Follow `docs/skill-frame.md`.

Search this checkout's `vault/` before a draft and before a claim about the owner's prior work. Start at `vault/README.md`. Search the wording you already have in the markdown under `vault/notes/`, `vault/sources/`, `vault/voice/`, `vault/posts/`, `vault/intake/`, `vault/week/`, and `vault/board.md`. Use the local file search, then read the file. Read the whole file behind every hit before you rely on it. A snippet only points at that file. Cite the path, and name what the file still leaves uncertain.

A page marked `Status: blank`, an empty note, and a template prompt are unanswered prompts. Owner context is a line the owner supplied. The same holds for a blank template under `brand/` or `audience/`: the frame reads `brand.local/` and `audience.local/`, and this search does not treat the template as a vault note. `vault/posts/sample-gate.md` is an example. Example files are not the owner's work. The README files in `vault/voice/` and `vault/sources/` only index those folders. A sample counts when the owner supplied that file.

Search the files in the checkout you have open. When this folder has moved, search the vault that is open now. Do not install software or a global server to answer a search. After a file under `vault/` changes, search again.

A note supports the words and the date written in it. A current fact from outside this desk stays open. This search does not establish it. No Dreamstate call.

After the owner accepts a piece, add one line to `vault/notes/concepts.md`: the concept, the post path, and the date they accepted it. Do not add a metric.
