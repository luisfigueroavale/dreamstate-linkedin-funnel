Follow `docs/skill-frame.md`.

Write this issue before the posts that reuse the argument. Read `brand.local/voice.md`, the owner files in `vault/voice/`, `audience.local/ideal-follower.md`, the week brief, and the offer pages `brand.local/identity.md` names. Read every supplied source from start to finish. If the voice file or the reader file is missing or blank, stop. Keep one useful idea and its promise to this reader. Other ideas wait for a later issue.

Earlier editions set the format. This draft must not become the house style.

Use four moves, in order: an opening observation, an explanation or a worked example, a practical application, and one next step. The explanation keeps the source's sequence. Add a heading only when it helps the reader. Do not add a heading that has no sourced sentence under it.

Name the guest whose experience you use. Put opinion and evidence in separate sentences. A metric names its population, its period, and its source. If any of those three is unknown, the number stays out of the body. Put a missing quote or fact on the source list, outside the body.

The subject and the preview promise what the issue delivers. Do not invent urgency. The preview promises what the subject did not already say.

Link labels name the destination. Open that page with `visibility.research.urls_fetch` per `docs/calls.md` before the sentence uses it. Every link carries `utm_source=newsletter` and the brief's weekly campaign slug. If the slug is blank, ask. Video URLs stay full https.

Paragraphs add information. Keep the owner's distinctive phrasing. Cut transitions that only announce the next move, and cut generic lessons the source did not earn.

Return the subject, the preview, the paste-ready body, and the outside list: each source, each confirmed link, and each gap. Use `split-long-source` only if they ask for other formats. Keep it a draft until the owner sends it. Do not send email. Use one file. Do not add a database or a second board to store it.
