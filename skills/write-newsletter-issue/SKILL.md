# Write a newsletter issue

Write one letter or newsletter issue with a single takeaway from sourced material.
Follow `docs/skill-frame.md`.

## Use when

- Use for the long written piece in a week. Write this issue before the posts that reuse the argument.

- Not for sending email. Use `split-long-source` only if they ask for other formats.

## Steps

1. Read `brand.local/voice.md`, the owner files in `vault/voice/`, `audience.local/ideal-follower.md`, the week brief, and the offer pages `brand.local/identity.md` names, and stop if the voice file or the reader file is missing or blank (`references/read.md`).

2. Read every supplied source from start to finish (`references/read.md`).

3. Keep one useful idea and its promise to this reader, and leave other ideas for a later issue (`references/shape.md`).

4. Draft four moves, in order (`references/shape.md`).

5. Open that page with `visibility.research.urls_fetch` per `docs/calls.md` before the sentence uses it (`references/links.md`).

6. Return the subject, the preview, the paste-ready body, and the outside list (`references/return.md`).

## Stop rules

- Follow the skill-frame writing rules.

- If the voice file or the reader file is missing or blank, stop.

- This draft must not become the house style.

- Do not add a heading that has no sourced sentence under it.

- If any of those three is unknown, the number stays out of the body.

- Do not invent urgency.

- If the slug is blank, ask.

- Video URLs stay full https.

- Do not send email.

- Keep it a draft until the owner sends it.

- Use one file.

- Do not add a database or a second board to store it.

- Use `split-long-source` only if they ask for other formats.

- Do not send dry_run to `visibility.research.urls_fetch`.
